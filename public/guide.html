PLS Studio user guide

PLS Studio is a browser editor for structural equation models: PLS-SEM and consistent PLS, covariance-based SEM, and conditional process analysis, with a log of further analyses. The numbers come from the reference R packages (cSEM, seminr, lavaan, manymome and others) running inside your browser, or in R on your own computer. Every result can be exported as the R script that produced it.

Getting started

The app opens on the home screen. From there you can start a new project (empty, or from a data file), open a saved project file, reopen a recent project, or open one of the examples. Projects you work on are kept automatically under Recent projects in this browser; File → Save project writes a portable .plsproj.json file that includes the data.

The editor has three tabs in the top bar:

  • Data: the dataset's rows, descriptive statistics and covariances.
  • Model: the diagram, with the variable list on the left and the Inspector on the right. The method switch (PLS-SEM / CB-SEM / CPA), Bootstrap and Calculate live here.
  • Analyses: a log of analysis cards (screening, factor analysis, prediction, segmentation, simulations and more), kept with the project.

The project name sits in the middle of the top bar; click it to rename. Undo and redo are next to the tabs (⌘Z / ⌘⇧Z, Ctrl on Windows and Linux).

The File menu

  • New project, Open project… (⌘O) and Save project (⌘S): project files are .plsproj.json and include the data, the model, the settings and the analysis log.
  • Import model syntax (lavaan, Mplus)… builds the diagram from pasted lavaan syntax (=~, ~, ~~, ~ 1, :=) or Mplus MODEL syntax (BY, ON, WITH; converted by lavaan); what the diagram cannot hold is listed. Download Mplus input writes the model as an Mplus .inp file with the data as a .dat file (TYPE = COMPLEX for sampling clusters, XWITH for moderations, MODEL CONSTRAINT for defined parameters). Inspect data opens the Data tab.
  • Create replication package… and Download R script: see Reports, scripts and replication.
  • User guide: this page.
The first calculation downloads the R runtime (a few hundred megabytes, cached by the browser). Later calculations start at once.

Data

Importing

Drop a file on the Data panel of the Model tab or choose one from the home screen. Supported: CSV (comma, semicolon or tab separated, with a header row), SPSS .sav, Stata .dta and Excel .xlsx / .xls (first row = variable names; you choose the sheet). Empty cells, NA and “.” count as missing. Text columns with few distinct values (groups, cluster ids) become categories.

For CB-SEM you can also import a covariance matrix instead of raw data (a labelled CSV as written by R's write.csv(cov(x))), give the sample size, and optionally an asymptotic covariance (NACOV) matrix for robust estimation.

The variable list

Filter variables by name; shift- or ⌘-click to select several. Drag variables onto the canvas to create a construct, or onto an existing construct to add them as indicators. Reverse-code… recodes negatively worded items (x becomes lowest + highest − x on the answer scale). Cases can be excluded from the analysis without editing the file; Restore brings them back. ƒ Compute… adds a column from a formula over the existing columns (log(income), (x1 + x2) / 2, z(score), ifelse(age >= 18, 1, 0); functions: log, log10, log2, exp, sqrt, abs, round, floor, ceiling, min, max, sum, mean, ifelse, isna, z, center, rank; names with spaces in backticks). Computed columns are marked ƒ; select one to edit its formula or remove it; they are recomputed after excluded cases are restored and saved with the project.

Missing values

The Inspector's Missing values setting applies to the model estimation: mean replacement, casewise deletion, multiple imputation (mice, with the number of imputed data sets), and for CB-SEM full-information maximum likelihood (FIML), pairwise deletion and two-stage (robust) estimation. With FIML or the two-stage approach, CB-SEM can take auxiliary variables: columns not in the model that make missing at random more plausible (lavaan’s aux =: saturated correlates with FIML, part of the first-stage EM with the two-stage approach; the model and its degrees of freedom do not change).

Drawing the model

The toolbar on the canvas has four tools: Select (V), Construct (C), Path (P) and Correlation (R).

  • Drag variables from the list onto the canvas to create a construct with those indicators, or onto a construct to add them.
  • Drag from a construct's connector dot to another construct to draw a path; drop a path on another path to make it a moderation (interaction).
  • Right-click a construct, indicator, path or empty space for the context menu: construct type, covariate, correlations, quadratic terms, labels and fixed values for parameters (variances, error variances, intercepts and thresholds too, with values per group when there are groups; listed under Labels, defined parameters, tests), ESEM blocks, free loadings and intercepts across groups, ordinal measurement, deleting, auto-arrange, and the Figure export.
  • The Inspector edits whatever is selected: name, construct type and weighting, dominant indicator, indicator side, measurement level, reliability of single-indicator constructs; and, with nothing selected, the estimation settings.

Ordinal indicators (right-click → Treat as ordinal) are estimated by WLSMV: diagonally weighted least squares on the polychoric correlations, with robust standard errors and a mean- and variance-adjusted χ². By default the standard errors are those of Mplus and of the classic WLSMV (Muthén, du Toit & Spisic 1997): the expected information in the sandwich and the covariance matrix of the estimates divided by N. Since version 0.7-2 lavaan puts the observed information there and divides by N − G, which can make standard errors differ, in exploratory rotations by several times; Standard errors under the estimator switches to lavaan 0.7’s convention (the EFA card has the same choice with polychoric correlations). Estimates and χ² are the same either way. Test statistic as Mplus gives the χ² Mplus prints (lavaan’s mimic = "Mplus"), for one group: with groups lavaan’s mimic also changes which parameters are held equal. Exported scripts carry the same settings.

Count indicators (right-click → Treat as count…: Poisson, negative binomial, zero-inflated Poisson or zero-inflated negative binomial) load on their factors through the log link. lavaan has no count indicators, so such a model is estimated by maximum likelihood with numerical integration over the factors (Mplus’s ALGORITHM = INTEGRATION): the Checks offer Estimate by integration, which opens the Integration ML card on the diagram (Analyses tab). The card shows the diagram written in its Mplus syntax (pairs of factors the diagram leaves uncorrelated held at 0; Edit as syntax copies it to edit by hand) and follows changes on the canvas. One group, ML or MLR, casewise deletion or FIML; ordinal indicators beside counts are logit; groups, levels, sampling weights or clusters, ESEM, latent interactions, composites, higher-order factors, defined parameters and imputation are refused with the reason. Validated by Mplus example 6.6 (a Poisson growth model) drawn on the canvas.

In the Inspector, Calculated by chooses the engine: the R packages in this browser, R on this computer through the helper (below), or the built-in PLS engine, which is validated against the packages.

Calculate and read results

Calculate (⌘↵) estimates the model; Bootstrap (⌘⇧↵) adds standard errors, t and p values and confidence intervals. Bootstrapping runs on all processor cores, each sample with its own seed, so results are the same whatever the computer. The eye button shows or hides the estimates on the diagram (path coefficients, R², loadings or weights).

The results panel below the diagram has tabs that depend on the method, for example Overview, Path coefficients, Indirect & total effects, Loadings, Model fit, Direct & indirect effects and Johnson–Neyman. Measurement tables include reliability (Cronbach's α, ρA, ρC), AVE, HTMT and HTMT2, Fornell–Larcker, cross-loadings, VIFs and f².

Every table can be copied as tab-separated text or downloaded as CSV (the buttons above it), and Snapshot to Analyses freezes the current results as a card on the Analyses tab, so you can keep several versions side by side.

Messages lists what the packages reported. Warnings (amber) concern the estimates: convergence, admissibility, what could not be computed; a calculation that raised one says so. Notes (grey) explain a result and flag nothing: a blank HTMT cell between nearly uncorrelated constructs, an item that correlates negatively with the rest of its construct, a package’s advice; the note also appears under the table it concerns. The examples run without unexpected warnings: the few warnings and notes an example’s own source produces (a documented model that fails on its data, a package’s advice on rescaling) are marked Expected in this example while it is open, each with the reason, instead of as problems.

The Analyses tab

Every Calculate logs a model run card: the model as it was, its estimation settings, which data it used, the diagram and the results. Calculating the same model again (or adding a bootstrap) updates that card; changing the model, a setting that affects the estimates, or the data starts a new version, and the card lists what changed (“+ path Trust → Loyalty”, “estimator ML → MLM”). The run that matches the model on the Model tab is marked current model; Open model on any run (also the ↗ next to it in the outline) puts that version back on the Model tab (undo returns), with its settings; on the Analyses tab, Calculate acts on the selected card: it runs an analysis card, or opens a model run on the Model tab and calculates it; if the model on the Model tab has changes that were never calculated, you are asked whether to keep them as a card. So the log is the history of your models.

Analyses are cards in a log: each has its options, a Run button and its result, and stays with the project. Headings and notes can be added between cards. A card can be renamed (the pencil on the card, double-click its title, or the Title field in the options pane): the name is shown on the card, in the outline and in the report; clear it to get the analysis name back. The outline on the right lists the cards; drag entries there to reorder. When the data or the model change after a card was run, the card is marked out of date with a button to rerun it. Results are stored compressed in the project; in a shared project the cards are shared and each person runs them on their own computer.

Available analyses, by group:

Data

  • Data screening
  • Missing data (patterns and their frequencies, covariance coverage, EM means and covariances, and dropout descriptives for repeated measures, as Mplus’s TYPE = BASIC prints them; Little’s MCAR test with each pattern’s share of its χ², and optionally Jamshidian & Jalal’s tests of equal covariances and distributions across patterns, by misty)
  • Missing data (patterns and their frequencies, covariance coverage, EM means and covariances, and dropout descriptives for repeated measures, as Mplus’s TYPE = BASIC prints them)
  • Chart (histogram, scatterplot with a least-squares line, box plot per group, bar chart; drawn in the browser, exportable as PDF, PNG or SVG)
  • Influential cases
  • Influential cases (generalized Cook’s distance and the change in χ² and fit per case by semfindr, an index plot of any of them, excluding a chosen case, and each case’s contribution to Mardia’s multivariate kurtosis)

Basic statistics

  • t-tests (one sample, paired, independent; Student, Welch, Wilcoxon signed-rank, Mann–Whitney; Cohen’s d, rank-biserial correlation, Shapiro–Wilk, Levene)
  • ANOVA (one or more between-subjects factors and ANCOVA covariates; type III or type I sums of squares; η², partial η², ω²; with one factor also Welch’s ANOVA, Kruskal–Wallis with pairwise rank tests, and Tukey’s comparisons)
  • Repeated-measures ANOVA (one within-subject factor from wide columns, an optional between factor; Mauchly’s test, Greenhouse–Geisser and Huynh–Feldt corrections, Friedman’s test, paired post hoc comparisons with Holm’s adjustment)
  • MANOVA (Pillai, Wilks, Hotelling–Lawley, Roy)
  • Correlation (Pearson, Spearman, Kendall; each pair tested, an interval for Pearson’s r)
  • Contingency table (Pearson and continuity-corrected χ², likelihood ratio, Fisher’s exact test, Cramér’s V, φ and the odds ratio for 2 × 2)
  • Binomial and multinomial tests
  • Reliability and agreement (Cronbach’s α with item statistics, McDonald’s ω total, the greatest lower bound; the six intraclass correlations of Shrout & Fleiss; Cohen’s kappa, unweighted and weighted; Bland–Altman limits of agreement with a plot)
  • Bayesian t-tests (one sample, paired, independent; JZS Bayes factors with a Cauchy prior on the effect size, JASP’s default width √2/2; one-sided alternatives; the posterior median and credible interval of δ; robustness check over prior widths and sequential analysis as plots; BayesFactor)
  • Bayesian correlation (Pearson; stretched beta prior, JASP’s default width 1; posterior of ρ; robustness and sequential plots)
  • Bayesian ANOVA and ANCOVA (every model that keeps its main effects against the null model, JASP’s prior widths 0.5 for factors and √2/4 for covariates; posterior model probabilities and inclusion Bayes factors per effect)
  • Bayesian repeated-measures ANOVA (a within-subject factor from wide columns and an optional between factor; the subjects as a random effect, every model against the subjects-only null model, as JASP)
  • Bayesian linear regression (every subset of up to ten predictors, JZS prior √2/4, beta-binomial or uniform model prior; posterior inclusion probabilities and Bayes factors per predictor, the most probable model’s coefficients)
  • Bayesian contingency table (Gunel & Dickey; joint multinomial, independent multinomial, Poisson or hypergeometric sampling; prior concentration 1)
  • Bayesian binomial test (beta prior, closed form)
  • Meta-analysis (one row per study: effect sizes with their variances or standard errors, or computed from means and SDs, 2×2 tables, correlations or proportions by escalc; equal- or random-effects models with eight τ² estimators, Knapp–Hartung tests, τ², I², H² and Q with Q-profile intervals, prediction intervals; meta-regression on continuous and categorical moderators; three-level models; forest and funnel plots; Egger’s test, rank correlation, trim-and-fill and PET-PEESE; influence diagnostics and leave-one-out; metafor)

In base R (stats) and psych, validated against direct calls of the same functions.

Measurement

  • Exploratory factor analysis
  • Common method bias (Harman’s single-factor test: one unrotated principal component or common factor of all the measures and its share of their variance, the 50% rule stated as the heuristic it is, with Podsakoff et al.’s caveats; full-collinearity VIFs: each construct regressed on all the others from the PLS construct scores, or any columns, against Kock’s 3.3)
  • Content validity index (an item × expert matrix of relevance ratings: I-CVI per item, S-CVI/Ave and S-CVI/UA, and the modified kappa k* of Polit, Beck & Owen with its evaluation bands)
  • Score-based invariance test (does the CB-SEM model on the canvas change along a continuous, ordinal or categorical covariate such as age, without making groups? Merkle & Zeileis’s tests on one lavaan fit by strucchange: double max, Cramér–von Mises and maxLM for a continuous covariate, WDMo and maxLMo for an ordinal one, LMuo for a categorical one, of the loadings, intercepts, variances or any set of parameters; the empirical fluctuation process with its 5% boundary, and each parameter’s own fluctuation)
  • Alignment optimisation (approximate measurement invariance across many groups, Asparouhov & Muthén 2014: the configural model of the diagram’s factors fitted in every group by lavaan, then sirt’s invariance.alignment gives each group’s aligned factor mean and SD, the aligned loadings and intercepts, R² of approximate invariance and the share of approximately non-invariant parameters within chosen tolerances)
  • Moderated nonlinear factor analysis (one factor of binary items, 1PL or 2PL, whose item intercepts and slopes and whose mean and SD depend on continuous or categorical covariates: DIF and impact in one model, with anchor items; mnlfa, without standard errors, compared by AIC and BIC)
  • Local SEM (the CB-SEM model on the canvas fitted at focal points of a continuous moderator such as age, each time to all cases weighted by a kernel around the point, so loadings, intercepts, variances and paths become curves along the moderator; optional bootstrap bands and a permutation test of each parameter’s variation; sirt’s lsem.estimate, lsem.bootstrap and lsem.permutationTest, Hildebrandt et al. 2016)
  • Effect sizes of non-invariance (dMACS) (each item’s dMACS between a reference and each focal group of the multigroup CB-SEM model on the canvas, configural or with partial invariance, Nye & Drasgow 2011: the expected item scores under the two groups’ loadings and intercepts compared over the focal group’s factor distribution by numerical integration, in pooled or reference-group SD units; signed dMACS and the expected bias in item and scale means and variances, Nye et al. 2019)
  • DIF by MIMIC (uniform differential item functioning of one factor of the diagram by a binary or continuous covariate: the factor regressed on the covariate, each item’s direct effect tested by a score test and by its own model with a Wald and a likelihood-ratio test, corrected by Holm, Benjamini–Hochberg or Bonferroni; optionally a final model with the flagged items’ direct effects freed; lavaan)
  • Two-level exploratory factor analysis (factors within and between clusters, geomin-rotated at each level; lavaan and GPArotation)
  • Item response theory
  • Latent class analysis (with auxiliary variables by the three-step approach: the classification errors of the assigned classes, distal outcomes’ class means with BCH weights and Wald tests, covariates of class membership by Vermunt’s ML three-step or BCH-weighted multinomial logit)
  • Latent class analysis
  • Mixture model (mixture regression, latent classes and latent transitions, factor and growth mixtures, two-level mixtures, written in Mplus’s own syntax for TYPE = MIXTURE; maximum likelihood with random starts, numerical integration where the classes hold factors or random effects, and robust standard errors)
  • Integration ML (factors and random effects with censored, count, categorical or survival outcomes, in Mplus syntax: maximum likelihood by numerical integration, with Mplus’s own integration rule)

CB-SEM model

  • PLS-SEM and CB-SEM compared
  • Parcel allocation variability (parcels are made in a construct’s panel: Make parcels…)
  • Bollen–Stine bootstrap
  • Parameter comparisons
  • Local fit (where the model misses: for every pair of observed variables the residual correlation with its standard error and z-test, lavaan::lavResiduals, as a heat-mapped matrix and a list of the largest misfits; the SRMR’s test of exact fit and the unbiased SRMR’s CI and test of close fit; Browne’s residual-based tests, Satorra–Bentler and Yuan–Bentler scaled, mean- and variance-adjusted and scaled-and-shifted tests with Hayakawa’s corrected trace, and the pEBA, pOLS and pALL tests, lavaan::lavTest, with the ML χ² or Browne’s RLS as the base; as JARS-Quant asks)
  • Discriminant validity (CI-CFA) (Rönkkö & Cho 2022: each factor correlation with its confidence interval from the CFA with unit factor variances, and χ² difference tests with the correlation fixed at .8, .9 and 1 (semTools::discriminantValidity), optionally against merging the two factors; each pair classified as no, marginal, moderate or severe problem by CI-CFA(sys) and χ²(sys), the paper’s Table 12)

  • EPC-based misspecification (every fixed parameter, such as a cross-loading or error covariance not drawn, judged misspecified, not misspecified or inconclusive from its modification index, expected parameter change and the power to detect a misspecification of the smallest size of interest, by Saris, Satorra & van der Veld’s (2009) J-rule and by the EPC’s confidence interval against that size, with the global verdicts; semTools::epcEquivFit; the sizes, α, power and a Bonferroni adjustment are options)
  • Specification search (as Amos: mark paths and covariances as optional on the canvas, right-click → Make optional, drawn dash-dotted; every combination of at most 12 optional arrows is fitted by lavaan, a left-out arrow fixed at zero, with the model’s estimator and missing-data treatment; the models ranked by BIC or AIC with χ², df, CFI, RMSEA, the rescaled criterion and its weight (Amos’s BIC_p), the best model for each number of parameters, and Apply to delete the arrows the chosen model leaves out)
  • Equivalent models (Lee & Hershberger’s replacing rules for the structural model, Stelzl 1986, MacCallum et al. 1993, Kline’s Rules 11.1–11.2: paths and covariances interchanged within a saturated block at the start of the model, and X → Y, Y → X or ζX ↔ ζY for two constructs with the same predictors; each alternative drawn as a small diagram and fitted by lavaan to confirm the same χ² and df, from two sets of starting values; Apply puts an alternative on the canvas; measurement models, covariates, higher-order constructs, ESEM factors, moderations and fixed or labelled arrows are kept as they are)
  • Multivariate LM and Wald tests (EQS’s stepwise model modification: the Lagrange multiplier test adds, among the fixed loadings, paths and covariances with the largest modification indices, the parameter that raises the multivariate score statistic most (lavaan::lavTestScore) while its univariate increment is significant; the Wald test drops the free path, covariance or loading that raises the multivariate Wald statistic least (lavaan::lavTestWald) while neither the increment nor the statistic is significant; cumulative χ², df and p, univariate increments, modification indices, expected parameter changes)
  • Informative hypotheses (order-restricted hypotheses on labelled parameters, one per line: b1 > b2 > 0, b1 = b2 & b3 > 0, linear combinations such as 2*b1 − b2 > 0.1, and abs(b1) > abs(b2) for sizes with the GORICA; GORICA values, penalties and weights against the complement, the unconstrained hypothesis or each other (restriktor::goric; Altinisik et al. 2021), and approximate adjusted fractional Bayes factors against the unconstrained hypothesis and the complement with posterior model probabilities (bain; Gu, Mulder & Hoijtink 2018); on unstandardised or standardised estimates; the seed from the Model settings)
  • Dyadic APIM (the actor–partner interdependence model of Kenny, Kashy & Cook 2006 from data with one row per dyad: each member’s X and Y as one column or the items of a latent variable; distinguishable or indistinguishable dyads; actor and partner effects, k = partner / actor with delta-method and percentile bootstrap intervals and the dyadic patterns they leave (Kenny & Ledermann 2010), the nonindependence correlations and the omnibus LR test of distinguishability; latent variables as dySEM’s scriptAPIM writes them; Draw on canvas puts the same model on the Model tab)
  • Regularised SEM (lslx, Huang, Chen & Weng 2017: the model on the canvas with cross-loadings, structural paths and/or residual covariances penalised by the lasso, ridge, elastic net or MCP over a grid of penalty levels (lslx’s own or from–to), the level chosen by BIC or AIC; the selected model’s fit, the penalised and free estimates with sandwich standard errors, and the path of the penalised estimates over the levels; ML or MLR, one group, continuous indicators, no labels; lslx was chosen over regsem because it takes the model’s lavaan syntax with pen() terms, converges over the whole penalty path and selects the level itself)
  • Factor scores (two tabs: Scores saves the model’s factor scores as data columns, by the regression or Bartlett method with optional standard errors (lavaan::lavPredict) or as plausible values (semTools); Weights shows the factor score weights that compute them from the observed variables; moved here from the Model fit tab)
  • Dynamic fit cutoffs (fit index cutoffs tailored to the model and sample size by the dynamic package of Wolf & McNeish: cfaOne, cfaHB, catOne, catHB, likertOne, likertHB, nnorOne, nnorHB, hier1HB, hier2, exactFit, equivTest and DDDFI on the model’s lavaan fit, the function suggested from the model’s shape; the package’s cutoff tables, the model’s indices against them, the simulated distributions; the Model fit tab links to the card and shows a current run’s cutoffs beside the fixed ones)
  • Bayesian SEM (blavaan, INLAvaan) (the model on the canvas by MCMC with Stan (blavaan): posterior means, SDs and credible intervals, R-hat and effective sample sizes, PPP, DIC, WAIC, LOOIC; runs in desktop R through the helper, as Stan does not run in the browser; or by INLAvaan’s approximate Bayesian inference (a Laplace approximation with skew-normal marginals, no MCMC), which runs in the browser too, in seconds: the same posterior summaries, PPP, DIC, WAIC, leave-one-out and Bayesian fit indices, with its diagnostics of the approximation (NMAD, VB shift) instead of R-hat, and default priors by parameter type; a new card in the browser starts with INLAvaan; factors identified by unit variances or markers)
  • Sensitivity to an unmeasured confounder (SEM) (a phantom variable with paths to the chosen constructs is added to the model, and SEMsens searches its coefficients by ant colony optimisation for the confounder that most changes the paths of interest: each path’s range, where its significance flips and with which phantom coefficients, a chart of a path’s estimate against the confounding strength)
  • Power analysis (semPower) (a priori: the N a test of fit needs; post hoc: its power at an N; compromise: the critical χ² balancing α and β; for misfit given as RMSEA, F0, Mc, GFI or AGFI on the model’s df or any df, with a power curve; the power to detect one parameter of the model, the fitted model taken as the population; and the RMSEA equivalence test, Yuan et al.’s T-size RMSEA against cutoffs adjusted for df and N)
  • Meta-analytic SEM (metaSEM) (two-stage SEM on the correlation matrices of published studies, one row per study with its N and a column per pair of the model’s observed variables named A_B: stage 1 pools them by fixed or random effects, with Q, τ² and I²; stage 2 fits the model on the canvas to the pooled matrix; runs in desktop R through the helper, as OpenMx does not run in the browser)
  • SEM trees (semtree) (the model on the canvas split recursively on covariates into groups whose parameters differ most, drawn as a tree with each node’s estimates; likelihood-ratio, score-based or fair split selection; optionally a SEM forest and its permutation variable importance; runs in desktop R through the helper, as OpenMx does not run in the browser)
  • Bayesian SEM (blavaan) (the model on the canvas by MCMC with Stan: posterior means, SDs and credible intervals, R-hat and effective sample sizes, PPP, DIC, WAIC, LOOIC; factors identified by unit variances or markers; runs in desktop R through the helper, as Stan does not run in the browser)

Regression and causal inference

Accounts and sharing

Without an account everything stays in this browser (Recent projects). Signed in, a project you work on is saved to your account as soon as it has a model or data (the toast says so): it appears under Your projects on the home screen on every computer you sign in on, its data stored encrypted on the server, and every change syncs as you work. Examples are not saved unless you keep one as your project. To work together, use Share in the top bar.

Your account

  • After registering, open the link in the verification email. Until the address is verified you can sign in but not share projects, invite people or accept invitations; the account menu can send the email again.
  • Forgot your password? on the sign-in dialog emails a link to choose a new one (valid for one hour). Accounts that use Google sign-in can set a password the same way (Set a password in the account menu).
  • Two-factor authentication (an authenticator app) can be turned on in the account menu; it also applies after Google sign-in.
  • Change password signs out your other devices.

Sharing a project

  • Share → Upload and share puts the project on the server. Your local copy stays in Recent projects; the shared version is listed under Shared projects on the home screen.
  • Invite people by email as editors (can change the model) or viewers. They receive an email with a link; the dialog also shows the link so you can send it yourself. Only an account with the invited address can accept, within 7 days.
  • Everyone with access edits the same model live, with cursors and presence; undo only reverts your own changes. Calculations run on each person's computer, and analysis cards are shared without their results.
  • The owner can change roles, remove people and withdraw invitations; members can leave.

Shared datasets are stored encrypted on the server (AES-256-GCM, a key per project).

Desktop R (helper)

The optional PLS Studio Helper runs the calculations in the R installed on your own computer: several times faster, on all cores, with every package available. Your data travel only between the browser and the helper, both on your computer.

  1. Install R (4.1 or later) and the helper, then run pls-studio-helper setup once to install the R packages into the helper's own library (your own R library is left alone).
  2. Start the helper (a PLS icon appears in the menu bar or tray). The helper answers only sites it trusts: for a deployment, allow its address once in a terminal, pls-studio-helper allow-origin https://your.site (on macOS the command sits inside the app: PLS Studio Helper.app/Contents/MacOS/pls-studio-helper), then restart the helper. PLS Studio shows the exact command when it cannot find the helper.
  3. In PLS Studio: Inspector → Calculated by → R runs in → Desktop R (helper), then Connect and allow the page in the helper's dialog. Without a tray, use a pairing code (pls-studio-helper pair).

PLS Studio falls back to the browser whenever the helper is not available. Disconnect forgets the connection in this browser.

Examples

The home screen offers a synthetic customer survey (PLS-SEM, raw data with a few missing values), the published model of Stol, Schaarschmidt & Goldblit (2022) on gamification in software engineering (CB-SEM from the covariance matrices of its replication package), Bollen's industrialisation and political democracy model, the MIMIC model of social participation (Jöreskog & Sörbom's LISREL example, the worked example in Schumacker & Lomax; a correlation matrix), and the documented examples of the R packages themselves (lavaan, cSEM, seminr, modsem, manymome, plspm, genpathmox, MatchIt, NCA, bootnet, EGAnet and others), each loading its data from the package and linking to its source. Each example card carries topic tags (CB-SEM, Moderation, Second-order, Multigroup, …); the package examples can be filtered by package and by topic. Examples open as the original each time, with the settings their source documents (bootstrap count, missing-value treatment, estimator), whatever the previous project used; only the diagram and chart styles carry over. Each card also says what the example shows: the result to look at and how to read it, with the source’s numbers where it gives them. While an example is open, the same text appears in a banner over the diagram on the Model tab and above the log on the Analyses tab; close it with its × to hide it for that example (remembered in this browser), and once the model, settings or data change it notes that it describes the example as it opened. Keep as my project turns one, with your changes, into your own project. A search box above the projects finds projects and examples by words in their name, title, description, package or topic.

Validation

Every example carries a badge for each kind of evidence its results were checked against, and the Validation page (from the home screen) lists every check. The record comes from the test suite, which runs each example and each method in the same R the app uses and compares the results with a reference that does not come from this app. The kinds are different evidence, not a ranking, and many examples have more than one:

  • Published: the numbers equal those printed by other people with other software (a book's tables, Mplus output, a paper), within the printed decimals. This shows that an independent implementation gets the same results, for the numbers the source prints.
  • Native R: the numbers equal the same R package run in desktop R on the same data (a reference script in the source, scripts/validation/), or the package's own documented output. This shows that the browser computes exactly what the package does, usually for every estimate and to four to six decimals.
  • Simulated: for methods without a reference package, simulated data with known true values, which the method recovers.
  • Runs: neither of these; the package's documented example estimates without an unexpected warning, and there are no independent numbers to compare it with.

Open a check to see every number compared: the app's value, the reference, the difference and the tolerance allowed, and the source. The Methods tab lists the methods' own tests beyond the examples. Check this browser runs ten examples, one per engine, in your browser and compares every number of their results with what the test suite computed, to six significant digits: it shows that your browser computes the same. When an example is opened and calculated unchanged, its results carry the same badge; it disappears as soon as the model, the estimation settings or the data are changed, since the check applies to the example as published only.
